## 2026-10-27 保存 Sites 与 OpenAI dot 部署讨论

以下保存前述对话的评估与待办，未在本次重新核验平台能力，也未执行云端部署。

- Sites：现有统一前端可作为适配对象；完整终端仍依赖独立的 Python API、Parquet/期权快照和用户状态存储。只上传静态页面不能提供行情、情景计算和保存功能；单独发布期货旧前端还会遗漏期权模块。私有框架预览与完整终端上线的范围尚未确定，因此尚未创建或发布本项目的 Sites 站点。
- dot：用户明确指 OpenAI dot 自带的云电脑。前述官方资料确认其有独立云电脑、可在本机关闭时继续云端工作并保留状态；这不足以验证本项目所需的固定访问入口、服务进程持续运行、资源限额及重启恢复。当前仅建议作为部署验证候选，尚无 dot 实机运行或长期托管验收结果。
- Wind 采集：继续依托可用且已授权的环境；云端不会自动继承本机 Wind 登录、解释器和 E 盘数据。后续可评估将校验后的行情截面同步至运行终端的环境，不能把连接本机等同于离线仍可取数。
- 如继续验证 dot：先用脱敏测试数据运行现有前后端，核对外部访问、闲置后运行、重启恢复及数据持久化；通过后再评估真实行情接入。若不满足长期运行要求，则由常规云服务器承载终端，dot 协助部署维护。未设定监控或自动任务。

前述评估参考：[dot 的云电脑与连接说明](https://learn.chatgpt.com/docs/dots/computers-and-apps)。既有本地终端及下方部署评估继续保留；这份记录不代表 Sites/dot 已上线或通过验收。

## 日常启动

推荐从统一工程启动：

```powershell
Set-Location 'E:\工作\期权终端'
./start.ps1
```

默认查看 http://127.0.0.1:8790/options/，顶部切换期货研究。也可以使用 `./start.ps1 --module futures`。

从期货目录沿用旧命令也进入同一终端：

```powershell
Set-Location 'E:\工作\期货终端'
./.venv/Scripts/python.exe start.py
```

对应 http://127.0.0.1:8790/futures/。这两个网址只是同一网页应用的两个模块路径，共用同一组后台服务。已有完整健康服务时直接复用，不再重复启动。首次启动器等待两个模块和入口就绪后才提示成功；端口被其他服务占用时退出，不强行关闭已有进程。

开发者明确需要单模块调试时，才运行 `start.py --standalone`，使用8766。该页面不作为统一终端的交付依据。

## 发布已验收的期货更新

1. 在期货源项目修改和完成本模块测试；候选/研究/生产准入边界继续遵守原HANDOFF。
2. 正常停止统一终端，不在使用期间替换构建产物和数据。
3. 执行一条明确的本地发布命令：

```powershell
Set-Location 'E:\工作\期权终端'
./tools/publish_futures.ps1
```

4. 命令刷新并校验期货前端副本、构建统一前端、发布固定后端、同步已保存的fundamental_lab与ceic_lab。使用已安装的Vite及本项目Python，不自动安装依赖，也不采集Wind或运行生产更新。
5. 审阅数据先暂存并逐文件校验，再替换本地展示副本，旧版保留。workbench.sqlite、期权行情指针和研究文件不被覆盖。运行中的8790/8794/8795会阻止发布。
6. 重新启动后，从8790检查变更模块及顶部切换；修改计划的请求经过统一网关。不能只在独立期货页看到新功能便认为整合完成。

构建或复制失败时，不继续启动未验收结果；按输出排查。当前发布脚本不是一次操作回退全部代码/前端/数据的事务发布器，遇到部分步骤完成时按下述各类备份恢复；云部署前再补齐整体发布目录与切换机制。
