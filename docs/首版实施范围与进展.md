# 首版实施范围与进展

2026-09-10。按“先做常用路径，不围绕corner案例扩建”的要求推进。

## 已实现的第一条使用闭环

- 一个React网页入口切换期货、期权；期货页面来自固定源码副本，统一API前缀和样式作用域。
- 期货API运行固定后端副本，使用本项目独立运行目录及虚拟环境。保留现有历史/基本面审阅功能和用途限制，不修改期货项目。
- 期权接入全月份MO目录、买卖盘口、实时量仓及前日OI、剩余交易日；保留原始Wind响应。
- 期权链、持仓叠加、真实IV点图、多腿方向和数量、目标/时间/IV情景，以及最大损益。
- 手动刷新时才调用Wind；当前截面不冒称持续实时。全部数据在本项目保存，旧分析源文件保留。
- 本地两个业务API与入口独立进程；不兼容/断源返回模块错误，不要求整个应用一起退出。

## 简化后的工程选择

本地首版使用现有FastAPI/httpx依赖作固定目标的同源转发，只有期货/期权两个白名单路径，没有通用网关框架。这样不额外安装代理服务。v0.4推荐的Caddy保留为云部署选择，当前不维护两套代理实现。

副本更新采用显式构建和哈希记录。暂不实现蓝绿发布、复杂兼容矩阵、自动恢复编排；源项目更新不会自动进入正在使用的终端，需要显式刷新副本并验收后重启。

## 首版仍未开放

- IO/HO/AU分析，持续订阅与自动调度。
- 自动候选排名、批量情景热力图、实际成交账簿及Greeks归因。
- 期权长期历史/昨日曲线联动、完整跨月矩阵、跨到期处置和保证金模型。
- 云数据发布/公开部署；代码未接入生产RDS写流程。

这些保留在v0.3/v0.4待实施清单，不把第一版称为全部方案完成。当前先完成MO手动截面与已有期货历史研究的统一使用。
