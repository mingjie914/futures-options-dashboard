# 跨机器运行与数据依赖

## 2026-10-29 只读服务与传输约定

保持 FastAPI/ASGI、统一同源 gateway 与席位、期货、期权三个独立 API。反向代理必须经过 gateway，不能绕过公开只读/同源校验。生产设置 `DASHBOARD_PUBLIC_READONLY=1`，三个 API 各一个 worker；静态资源单独发布，不在请求中构建。启动健康检查只检查进程，不加载行情、回补历史或调用供应商；行情解析/统计在第一次实际查询时按需执行。

| 预算变量 | 单进程默认 | 覆盖范围 |
|---|---|---|
| `FUTURES_CACHE_MB` | 96 MiB | 日线对象、雷达、持仓峰值和 HTTP 正文共用 LRU |
| `OPTIONS_CACHE_MB` | 32 MiB | 历史截面、IV 历史、前次截面和 HTTP 正文共用 LRU |
| `DASHBOARD_CACHE_BYTES` | 134217728 B | 席位 API 响应缓存 |
| `DASHBOARD_QUERY_CONCURRENCY` | 1 | 席位查询并发 |
| `OPTIONS_ACTIVE_MB` | 16 MiB | 另计的当前规范化截面；超过预算拒绝加载 |
| `FUTURES_HTTP_CONCURRENCY` / `OPTIONS_HTTP_CONCURRENCY` | 各 1 | 未命中缓存的 GET 计算并发 |
| `FUTURES_QUERY_CONCURRENCY` | 1 | DuckDB 查询并发，含基本面/指数 |
| `FUTURES_DUCKDB_THREADS` / `FUTURES_DUCKDB_MEMORY` | 1 / 256MB | 每个 DuckDB 连接；禁止临时落盘 |

期货与期权缓存合计 128 MiB，席位独立缓存默认 128 MiB，三 API 合计 256 MiB；增加 worker 会成倍增加预算。以上不是 RSS 上限：Python、当前截面、查询中间结果及响应编码另占内存；应继续由 systemd/cgroup 限制进程组。浏览器另有约 8 MiB 的正文 LRU，仅驻留当前页面内存，不写浏览器存储，关闭/刷新后按需重建。

期货、期权和 gateway 共用 `futures/backend/transport.py`；席位保留自己的版本/快照响应缓存。三个 API 复用 `futures/backend/dashboard_json_delta.py` 的纯 JSON 差量算法；席位安装包包含该模块，更新时须从完整仓库重新安装席位包。三模块浏览器共用 `frontend/src/transport.js`。gateway 向上游请求 identity，再在边界对达到 1 KiB 的响应使用 gzip level 4 压缩一次。ETag 使用弱校验值，身份/压缩表示共用版本；`Vary` 包含 Accept-Encoding、A-IM，304 无正文。上线后仍需在真实 Caddy 路由复验。

版本包含源码/公式版本、完整查询参数、输入文件指纹；日线还包含当前日期。指纹覆盖文件大小、纳秒修改/创建时间及 inode，新增/删除分区也会失效。**发布输入必须使用临时文件校验后原子替换，或发布不可变目录并原子切换指针；不得原地改写并恢复全部文件属性。** 同日修订也必须产生新指纹，不能只以最大交易日作版本。已有正文被逐出后，合法的相同版本请求仍可直接 304，无需重做统计。

版本变化时，浏览器发送 `If-None-Match` 和 `A-IM: dashboard-json-delta`；服务器保留旧正文且差量小于完整正文 80% 时返回 226：`{base, version, ops}`。`set/remove` 路径操作明确表达空值、修订、增加和删除，浏览器验证旧版本并还原完整 JSON。没有旧版本、差量过大或校验失败时退回完整 200；这是有限缓存内的响应差量，**不是持久跨批次 CDC，也不保证每次都只传变化行**。未变化是 304，不称作差量。断网/进程重启/缓存逐出均允许完整恢复。既有明细接口继续提供区间/字段/分页和 snapshot_id；分页版本变化返回 409，不能拼接两批数据。

### 输入、计算与最小存储

席位 `--p2-only --full` 从完整 Parquet 集生成新快照。生产日常流程目前仍为窗口刷新、分区差量交付、全量派生；新增的分区增量构建候选须经云端全历史验收后启用。`--date` 只发布单日 marts，不能当作日常追加；`--reclassify-from` 只重算分组，不能导入行情修订。抽取、交付、离线计算与 HTTP 差量分别验收。

```sh
python -m seat_dashboard.jobs.build_snapshot --p2-only --full --seat-root /data/seats --market-root /data/market/futureshistoryprices1d --runtime-root /runtime/seats --seat-tag-config seats/config/seat-tags.csv --combination-config seats/config/combinations.json --product-config seats/config/products.csv
```

分区增量候选沿用相同数据根与配置参数，将 `--full` 换成：

```text
--incremental-from <基线席位runtime> --base-input-manifest <基线输入manifest.json> --input-manifest <新输入manifest.json>
```

新输入须为完整分区树；`changed_months` 按表声明完整月替换，含整月删除。新清单的 `base_batch`、`base_manifest_sha256` 必须绑定基线输入；构建器核对基线 DuckDB 内的来源摘要、当前文件哈希及未申报分区变化，缺失或不符即拒绝，由调用方显式选择全量回退。无变化由调用方跳过，不发布空增量。

构建复制不可变基线，只重新规范化/聚合变更月及最新合约截面所在月，替换四张日度表相应月份并修复跨月前日差分。主力覆盖从更新后的完整日价/品种日历重算；信号、分位、未来收益验证继续使用完整历史重算。未改动行保留原 `batch_id` 来源标记，API 版本由新发布清单确定；旧库、上游数据与线上指针不被候选构建修改。已通过新增、修订、整月删除、最新月删除、日价单独变化、日历扩展及真实一月/十月样本的逐表等价测试；不据此宣称全历史性能验收完成。

数据更新不要重启 API，否则会丢失差量基线。席位使用稳定、非软链接的运行目录，原子替换 `manifests/current.json`，其中 `database_path` 指向不可变快照；不设置固定 `DASHBOARD_SNAPSHOT_PATH`。期货允许 `FUTURES_DATA_ROOT` 经过原子切换的目录软链，每次 HTTP 请求固定解析后的根路径，版本与多次查询使用同一批输入。保留旧发布物直到在途读取结束；跨模块数据水位仍独立。

生产日线保留一套只读 Parquet 分区，API 不复制全量源，也不执行采集任务。公开模式关闭每次查询的 JSON 快照及 latest 指针写入；旧本地模式仍可使用原先降级快照。前端所需历史应在首次数据发布时一次准备完整授权窗口；此后由**上游数据项目**按源水位、变更分区和删除清单更新，不由网站启动触发。

网站内的可复现计算位于 `futures/backend/analytics.py`、`futures/backend/data.py`、`backend/data.py` 与 `backend/pricing.py`，跟随代码版本。基本面离线重放已有 `futures/tools/fundamental_lab.py`（prepare/update-review/index-update）和 `ceic_lab.py`，输入已保存证据；`--fetch` 属于单独采集授权。`tools/freeze_backend.py` / `tools/publish_futures.ps1 -CodeOnly` 发布代码，不回补数据。

增量发布必须区分追加与修订：追加仅同步新/变更分区；修订窗口由各数据源已有规则确定，不能在网站里默认成“只补最近一天”。涉及修订的合约历史、同比/季节统计和分位需要按依赖历史重算；本次采用源版本失效后按需重算，尚未新增通用后台预计算任务或跨机器水位同步器。重建历史、更换公式属于显式离线作业，不能藏在健康检查/启动路径中。

云端最低保留当前有效数据及被界面读取的必要历史、一版回滚、一个受容量约束的 staging；当前与回滚未变化分区可共用不可变文件或文件系统硬链接。期权归档仍由比较/历史接口读取，不能简单只留下两个日期。外部采集原件与研究证据留在其权威存储，云端仅接收所需发布物；不要同时长期保留同一日线的数据库导出、CSV、Parquet、查询 JSON 多份副本。生产保留/清理策略需先列出实际依赖再执行；本轮没有删除原始数据、历史证据或本地用户记录，也没有创建自动清理任务。

2026-10-28 历史验证（最新结果见《部署与统一维护入口》）：期权/整合测试 53 通过、1 跳过；期货 229 通过、5 跳过；前端与差量 24 通过，统一构建通过。真实本地 HTTP + Node 前端模块完成 `200 → 226 → 304 → 200`，验证修订、删除、空值和服务端缓存丢失恢复；该项使用隔离测试数据，没有改动真实行情。8790 实际 RB 换月、五年同月持仓、期权截面 gzip 正文分别减少 76.3%、81.3%、72.0%；单客户端 304 分别约 22、22、4ms，仅为本机样本，不代表云端压测。浏览器期货/期权刷新实见 304，页面图表正常，无相关控制台错误；修复换月刷新时一轮随后取消的重复请求。尚待生产 Caddy、真实多用户负载及发布/修订流水线联验。

## 运行与配置

首次准备按根 README 创建三套独立虚拟环境、安装锁定依赖。无需基本面私有原件时，可从根目录执行 `./tools/publish_futures.ps1 -CodeOnly`；它构建统一前端并准备期货后端，保留已有运行数据，不调用 Wind。需要显式同步已保存基本面原件时仍使用不带 `-CodeOnly` 的原命令。两种发布均须先正常停止统一终端。

运行 `./start.ps1`，日常入口为 http://127.0.0.1:8790/options/ 。Linux 按 README 使用虚拟环境的 `bin/python` 执行 `start.py`；本轮未完成 Linux 实机验收。

环境变量使用绝对路径；未配置时使用下表默认值。云端由进程管理器注入相同变量，不需要复刻开发机目录。

| 变量 | 默认值 / 用途 |
|---|---|
| `OPTIONS_PYTHON` | `<仓库>/.venv/Scripts/python.exe`；Linux 为 `bin/python`，入口与期权进程 |
| `SEATS_PYTHON` | `<仓库>/.venv-seats/Scripts/python.exe`；Linux 为 `bin/python`，独立席位进程 |
| `SEATS_RUNTIME` | 默认 `<运行根>/seats`；席位 manifest 及只读发布快照 |
| `FUTURES_PYTHON` | `<仓库>/.venv-futures/Scripts/python.exe`；Linux 为 `bin/python`，独立期货进程 |
| `DASHBOARD_RUNTIME_ROOT` | `<仓库>/runtime`；期货发布清单、冻结后端、日志、会话及默认期权运行状态 |
| `FUTURES_RUNTIME` | 统一启动器按发布清单设置，默认 `<运行根>/futures`；审阅快照、自选、研究计划及日线缓存。仅直接运行期货 API 时手动设置 |
| `OPTIONS_RUNTIME` | 默认运行根；期权选版指针和刷新错误日志 |
| `FUTURES_DATA_ROOT` | `<仓库>/futures/data`；可指向包含 `futureshistoryprices1d` 的父目录，或直接指向该目录 |
| `OPTIONS_DATA_ROOT` | `<仓库>/data/raw`；已保存 Wind 响应的目录集合，手动刷新也写在这里 |
| `OPTIONS_SNAPSHOT_DIR` | 无默认值；没有选版指针时，显式读取一份已保存原始快照目录 |
| `OPTIONS_WIND_PYTHON` | 无默认值；不配置则关闭手动采集。读取既有快照不依赖 WindPy |

例如，将运行状态与行情目录挂载到仓库之外，在当前 PowerShell 会话设置后发布、启动：

```powershell
$env:DASHBOARD_RUNTIME_ROOT = 'D:/dashboard-state'
$env:FUTURES_DATA_ROOT = 'D:/market-data'
$env:OPTIONS_DATA_ROOT = 'D:/options-archives'
./tools/publish_futures.ps1 -CodeOnly
./start.ps1
```

以上仅是配置示例，须换成本机已核验目录。本轮未把本机其他项目的行情自动接进来。

## 数据仍需明确提供

| 功能 | 读取契约 | 缺失时行为 |
|---|---|---|
| 期货日线、跨期、雷达、持仓历史 | `futureshistoryprices1d/year_month=YYYY-MM/*.parquet`，沿用现有字段与真实月份合约筛选 | 品种列表为空，研究/雷达接口明确返回 503；有历史缓存时沿用原有 stale 标记 |
| 期权截面、IV、情景分析 | 完整已保存响应目录：`chain.json`、`quotes.json`、`collection.json` 及对应日线/前日数据等 | 状态为 `empty`，快照接口返回 503；显式配置但损坏或不存在的快照按错误处理 |
| 基本面、指数收盘基差、CEIC候选 | 期货运行目录中的 `fundamental_lab` / `ceic_lab`，原选版指针、哈希、元数据及用途限制不变 | 显示缺失/校验失败；不补造指标，不因移机放宽业务准入 |
| 自选与研究计划 | 独立运行目录内 `workbench.sqlite` | 可创建本机状态，不要求行情源存在 |
| Wind手动刷新 | 显式配置的解释器及其中可用的 WindPy、授权终端 | 未配置或解释器不可用时返回明确错误，保留已有快照与指针 |

期权新生成指针用 `path_base=options_data_root`，目录名相对 `OPTIONS_DATA_ROOT` 保存；运行状态和归档整体移机后只需重设数据根。兼容旧绝对指针及相对仓库指针，但旧机绝对路径不会自动猜测映射；可显式配置 `OPTIONS_SNAPSHOT_DIR` 读取复制后的原始目录，或人工核对并迁移旧指针。已有指针优先，损坏指针必须先修复，不能借配置静默绕过。

期货新发布清单用 `path_base=runtime_root`，后端与运行目录相对运行根保存；兼容旧的相对仓库清单。源路径等历史证据保留原值，不伪造为本机来源。迁移已有私有数据前需核验哈希，源码克隆不等于数据迁移。

## 离线研究工具的可选输入

这些输入只供显式运行的研究/审计命令使用，应用启动不读取外部工程、不触发取数。

| 配置 | 用途 |
|---|---|
| `FUNDAMENTAL_REGISTRY` 或 `inventory --registry` | 基本面登记文件，默认 `futures/data/fundamental/indicators.json` |
| `FUNDAMENTAL_PROJECT_ROOT` | 旧登记表/工作簿只读审计输入，默认 `futures/data` |
| `FUNDAMENTAL_WIND_PYTHON` | 隔离基本面取数解释器，回退到显式 `OPTIONS_WIND_PYTHON`，否则使用当前解释器；仍须显式执行取数命令 |
| `CEIC_PROJECT_ROOT` 或 `ceic_lab.py --project` | CEIC宽表登记与既有 `ceic_growth_web_export.py` 解析器所在目录，默认 `futures/data/ceic` |
| 各命令的 `--source-root` | 覆盖只读 Parquet 输入；默认沿用 `FUTURES_DATA_ROOT` |

CEIC新XLSX审计仍需外部解析器和 pandas/openpyxl；这是可选离线导入依赖，未纳入应用在线运行。云端可只读取已核验、带完整审计的快照包，采集/导出留在有授权环境。本轮没有迁入外部工程或改写解析规则。
