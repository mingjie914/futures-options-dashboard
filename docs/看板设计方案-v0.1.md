## 产品目标

把长篇期权分析变成盘中可快速操作的工作台。目标是：10秒识别市场变化，30秒比较候选合约，1分钟核查一笔交易在不同退出情景下的收益与风险。上述为设计目标，后续需要实际任务计时验证。

默认从中证1000开始：MO期权＋000852现货＋IM实际月份期货。月份跟随权威挂牌目录滚动，不把2609/2610写死。可选择任意已支持月份，多月对比优先两个月。其他标的、不同结算方式以后逐类接入，不直接套用MO模型。

首页默认买方视角，但保留完整市场分析及组合比较入口。盘中信息不依赖大模型生成：原始行情、自算指标和情景重估确定性输出；文字解释点击后展开，不占据主屏。

## 页面安排

| 页面 | 主要回答的问题 | 核心图表/操作 |
|---|---|---|
| 交易工作台（默认） | 当前变化是什么；买哪份；如果提前退出会怎样 | 市场状态条、分时图、候选比较、情景热力图 |
| 波动率 | 绝对波动贵不贵；哪侧贵；月份差异是什么 | OTM微笑、25Δ/10Δ偏度、曲率、期限结构、IV/RV历史 |
| 持仓与成交 | 哪些档位集中；是新增还是旧仓；是否迁移 | Call/Put分布、增减仓、执行价×日期热力图、选中合约历史 |
| 完整期权链 | 某一份合约的原始报价与风险指标是什么 | 按执行价对齐的Call/Put链、筛选、加入对比 |

历史回放为全局日期/时刻模式，不另造重复首页；首版先保证保存截面的复现，后续开放时间轴播放。自选合约及比较篮跨页面保留。

## 首页布局与视觉原则

桌面宽屏优先。首屏上方为窄状态条，下方两层内容，避免长页面滚动。

1. 顶部：标的、比较月份、实时/历史、行情时间、交易状态、数据质量；支持冻结当前比较截面。
2. 主区左侧约60%：现货/期货分时，明确分别标轴；目标价、观察位叠加。下方为最多4份候选合约的比较表。
3. 主区右侧约40%：交易意图与情景面板，输入目标点位、计划持有时间、IV变化、预算；显示情景损益热力图及候选差异。
4. 底部窄条：最多3条有证据的变化提示，例如“7700C持仓较昨日增加”“25Δ偏度较昨日下降”；点击打开相应研究页，不输出无依据的买卖指令。

视觉建议：紧凑终端式排版、低饱和底色、清晰数字对齐；优先复用期货终端的字型、间距与图表交互，再通过Product Design优化。先不锁定最终深浅色或布局美术稿。对比用蓝/橙区分合约，涨跌同时给正负号；告警不用单一红绿色传达。

优先显示“金额、目标下收益、成本、时效”，希腊字母细节可展开。所有金额单位明确区分元/手、点、百分比、波动率百分点。盘中行情更新不自动重排行，不把鼠标下的候选换掉；用户主动排序或刷新排名。图表缩放、筛选和已选合约在更新后保持。

交互联动：点击某个持仓柱→打开该执行价的Call/Put历史→一键加入比较；点击微笑曲线点→定位真实合约；修改目标价→分时目标线、候选表和情景热力图一起更新。

## 核心：合约比较与提前退出情景

输入尽量少，默认项直接可用：

- 方向：看多/看空；范围：纯买方/包含价差组合。
- 当前参考：中证1000现货或指定IM合约，名称完整显示，不能混用点位。
- 退出目标：例如现货7700、7750、7800；时间：当日指定时刻、下一交易日、3交易日或指定日期。实际模型用明确的经过自然时间和交易日历，不把1交易日机械当作1/365年。
- IV情景：-2、0、+2个百分点，支持自定义；基差变化放入高级设置，默认“基差不变”醒目标注。
- 比较口径：每1手、相同权利金预算、相同初始Delta敞口。默认先显示每手，切到预算时向下取整到可交易手数，并展示未使用资金；不生成小数手、不突破风险预算。

候选表默认列：合约、买入成本、买卖价差、Delta、每日时间损耗（元）、IV变动1点影响（元）、目标情景净损益、最大权利金损失、报价状态。更深的Gamma、Vanna、Volga等按需求展开，首版不为堆指标而增加页面。

热力图横轴为标的价格，纵轴为退出日期；IV用场景切换，多个候选可并排。另提供同一退出日期的P&L曲线，并可切到“到期损益”作为独立模式。悬停明确模型价格、买卖成本、费用假设及使用的行情截面。

不把“到期盈亏平衡点”作为提前止盈的唯一筛选。模拟涨到7700，并不假定已经在7700入场；若用户设置突破后入场，需要单独选择假定入场价格和时刻，重新估值成本。

已建仓模式：允许用户手动填写实际成交成本、时间与手数；只读分析，不连接交易下单。持仓按可退出方向报价估值，历史实际成本不能被当前卖一覆盖。

情景损益是条件估值，不给无依据的胜率/成功概率，也不做神秘综合评分。标签使用可核查描述，如“Delta较高”“价差较宽”“降波敏感”，并能展开数字依据。

## 波动率与量仓分析

波动率页：

- 两个月份OTM微笑叠加，可按执行价、K/F或Delta切换，避免把不同月份同执行价误当作相同虚值程度。
- 昨日/指定历史截面对照；筛选有效双边报价，低流动性点使用不同标记，提供IV bid/ask区间。
- ATM IV、25Δ/10Δ Put−Call偏度与蝶式曲率代理；同时列定义，不把偏度收敛写成微笑消失。
- 期限同时显示自然日IV、剩余自然日/交易日、总方差和交易日归一化视图，长假不可隐藏。
- RV分别显示收盘收益与分钟实现波动，注明采样频率、隔夜处理、年化和样本数。历史覆盖不足时不提供IV分位或伪造长期区间。

持仓页：

- Call/Put持仓量与当日成交量分开；日增仓与盘中OI更新分开。
- 前1/5交易日同一真实合约对比，三档集中度、执行价分布、换月至远月的变化。
- “大持仓＋增仓＋IV变化＋标的走势”并列，避免只看OI柱状图。
- “Call墙”只是持仓集中区。总OI不能识别买卖方身份，不默认生成有符号的做市商GEX、Gamma翻转点或逼空概率。
- 最大痛点如保留，只放研究展开项，标为静态到期支付计算，不放首页方向提示。

## Wind数据与估值口径

已在本任务验证：wset期权链，wss日线截面量价持仓，wsq买卖报价，wsd历史，wsi分钟数据和交易日历。尚未验证：持续订阅稳定性、当前账户订阅数量/频率限制、盘中OI更新行为与逐字段同步精度。因此不能把首版直接承诺为逐笔实时交易终端。

建议初始刷新目标：

| 数据 | 更新方案 |
|---|---|
| 合约、到期日、乘数、交易日历 | 日初一次并缓存，必要时手动刷新 |
| 当前链和自选买卖盘 | 优先单一进程订阅；不支持时按账户限额进行批量轮询，初始目标5—10秒 |
| 当前指标/首页 | 跟随已通过质量检查的行情截面；情景输入变化复用缓存，不额外请求Wind |
| 持仓 | 有已验证的盘中字段才标盘中；否则标截至上一交易日或日终，不显示成实时增仓 |
| 分钟历史/快照 | 分钟级保存聚合快照；按需回补已有窗口缺口，不逐次重复全历史 |
| 正式收盘数据 | 盘后手动触发并核对数据日期；自动化采集以后另行明确时段 |

每个截面保存源时间、接收时间、交易日期和字段状态；同一屏幕比较使用共同snapshot_id。共同snapshot_id不代表不同合约逐笔同步，还需要时间偏差检查。不把盘后记录更新时间当作真实最后成交时间。闭市显示“收盘归档”，连接断开显示“冻结于…”，不能靠页面时钟更新伪装成新行情。

价格用途严格区分：历史走势用收盘；展示盘口用bid/ask；基准IV用合格双边中价；实际模拟买入取ask、退出取bid或模型中价扣可配置价差。结算价另列，不替代收盘或可交易报价。多腿成本按每腿相应方向计算，不能把全体中价之和标作可成交价。

MO估值基于欧式远期模型：优先同步平价反推F，与IM交叉检查；资金利率、期限和远期选择显式记录。希腊值默认对远期求导；模拟现货目标时需明确现货到远期的基差假设。

情景默认保留当前曲面，在指定IV变化下重估，不把所有执行价替换成一个ATM IV。初期采用固定执行价IV平移假设，并醒目标明；高级曲面动态等有明确需求再做。到期交割参考最后两小时指数均价，不能与盘中触价混为一谈。

坏价规则：缺腿、bid>ask、报价过旧、深实值不满足定价边界、IV不可解，分别显示原因；不填0或用昨收冒充实时。底层API和原始证据保留，可从任意指标点击追溯。

## 本地技术路线与未来公开

已查看引用任务《分析网站架构与技术栈》及E:\工作\期货终端的当前README、依赖和交接文件。该本地项目已采用React＋Vite＋ECharts和FastAPI＋DuckDB；最早分析的远程示例是静态HTML/JS模式，两者不可混称为同一套实现。

本项目建议沿用当前本地项目的技术组合：

Wind（本机已授权环境）→单一取数进程→本地行情缓存与归档→Python计算/FastAPI→React＋ECharts浏览器界面。

- Web请求不直接启动Wind，也不为每个页面重复订阅。取数进程统一管理自身请求，可复用已验证Wind环境，Web依赖使用本项目独立环境；不修改已有生产环境。避免对共享Wind会话调用全局停止。
- 最新行情内存缓存；历史按日期保存Parquet，由DuckDB查询；自选、实际成本和界面偏好用一个SQLite文件。单写者发布完整快照，浏览器不会读到半批更新。
- 本地单机初版不引入Redis、Celery、微服务或账户体系。一条统一计算路径服务界面与报告，避免图表和表格使用不同公式。
- UI与取数通过明确的数据接口隔离，便于以后把网页/API部署到服务器；Wind采集是否留在本机、改为授权服务器接口，届时单独选择，不能假定当前终端授权可直接搬到云端。
- 对外公开前必须核实所用行情及衍生数据的再分发许可与账户合同范围，不能假定“能本地查询”就能公开展示。这是待核实的部署条件，不影响当前本地设计。
- 未来公开API应与本地管理/刷新入口隔离；当前只监听127.0.0.1，不开公网、不上传数据。

参考：[Wind Client API](https://www.wind.com.cn/portal/zh/ClientApi/index.html)、[FastAPI部署说明](https://fastapi.tiangolo.com/deployment/concepts/)。官方资料仅支持技术路线，当前账户权限和公开许可仍以实际合同/实测为准。

## 分阶段与验收

1. 本轮：方案讨论，确定首页重心。默认建议“合约比较＋提前退出情景”优先。
2. 视觉方案：用Product Design给首页出视觉方向，使用明确标注的9月9日历史样本；先选界面，再实施。不是在方案阶段直接搭站或部署。
3. 可用首版：MO当前/次月、统一目录、数据质量状态、首页比较与情景、完整链、基础微笑/量仓页。可手动刷新，接入Wind需先完成小规模盘中字段和时效验证。
4. 盘中增强：持续采集、价格/IV/P&L本地提醒、历史回放、实际持仓跟踪；提醒由明确条件触发，支持静音、去重和冷却，不自动下单。
5. 扩展与公开：增加其他标的和更长历史，取得相应授权后讨论云部署。

必须通过的验收：130份已存样本复算及坏价保留；单买/价差按买卖方向计价；交易日跨周末/长假时间正确；现货/期货目标不串用；同预算手数不越界；断源、旧价、缺腿在界面明确；快照可重复复算；输入与联动实际点击可用；字体、图表刻度和比较表在真实屏幕无重叠。不会用“构建通过”替代真实数据与界面验收。
